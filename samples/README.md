# TechArena Solver — примеры посылок и правила проверки

В этом каталоге лежат **учебные примеры** (не эталонные решения задачи). Они показывают, как устроены вход/выход и как отправлять код в NSUTS.

| Файл | Описание |
|------|----------|
| `examples/standard_main.cpp` | «Стандартный» C++ (один `.cpp`) |
| `examples/standard_main.py` | «Стандартный» Python (один `.py`) |
| `examples/Main.java` | «Стандартный» Java (`Main.java`, public class `Main`) |
| `docker_standard_cpp.zip` | Docker: C++ + `Makefile` |
| `docker_standard_python.zip` | Docker: Python + venv в `Makefile` |
| `docker_standard_java.zip` | Docker: Java + `Makefile` |
| `docker_standard_julia.zip` | Docker: Julia + `Project.toml` + `Makefile` |

Примеры читают **`instance.json`**, пишут **`solution.json`** и строят простое допустимое решение (один офис, один site).

---

## Общие ограничения

### Время и память (на один тест)

- **Время:** 5 минут на один прогон (один инстанс в пакете тестов).
- **Память:** 8 ГиБ на процесс в контейнере / под лимитом тестера.

### Файлы ввода и вывода

Имена **фиксированы для тура**:

| Файл | Назначение |
|------|------------|
| **`instance.json`** | Вход: один инстанс задачи |
| **`solution.json`** | Выход: ваше решение |

Программа запускается в каталоге, где лежат эти файлы (в Docker — **`/solution`**, рядом с вашим проектом). Открывайте их **по этим именам**, не полагайтесь на произвольные пути.

### Формат `instance.json`

Один JSON-объект:

- **`sites`** — массив site: `x`, `y`, `reward`, `tasks` (массив id типов работ, **с нуля**).
- **`offices`** — массив office: `x`, `y`, `cost`, `maxSize`.
- **`workers`** — массив работников; у каждого — массив id навыков (**с нуля**).
- **`distances`** — матрица `distances[office][site]` (неотрицательные числа).
- **`maxDifference`** — допустимый разброс числа site между открытыми офисами.
- **`balanceCoefficient`** — штраф за дисбаланс загрузки офисов (см. условие задачи).

### Формат `solution.json`

JSON-массив открытых офисов. Каждый элемент:

```json
{
  "officeId": 0,
  "sites": [1, 4],
  "workers": [0, 2]
}
```

- **`officeId`**, **`sites`**, **`workers`** — индексы **с нуля** в том же смысле, что в `instance.json`.
- Один site и один worker не могут встречаться в двух офисах.
- Должны выполняться ограничения задачи (ёмкость офиса, навыки, баланс, геометрия зон и т.д.).

Если решение **невалидно**, получите **Wrong Answer** с текстом ошибки в отчёте. Если прогон упал (RE/TLE/MLE) — балл за этот прогон не начисляется.

### Оценка

За **валидное** решение считается **objective** (максимизируется):

`reward − distance − opening_cost − balanceCoefficient × imbalance`

В протокол попадают **сырые** значения по инстансам; в рейтинге они нормируются относительно лучших известных результатов по туру.

## «Стандартные» решения (компиляторы NSUTS)

Подходят компиляторы вроде **g++**, **python3**, **java** (конкретный список — в интерфейсе отправки).

- Отправляется **один самодостаточный исходник** (или один файл, который принимает выбранный компилятор): без ручной сборки на стороне участника.
- Вся логика — в этом файле (или в разрешённых для компилятора правилах); **внешние файлы проекта** в посылку не упаковываются.
- Программа должна **прочитать `instance.json`** и **записать `solution.json`** в текущий каталог.
- **Не печатайте лишнее в stdout**, если компилятор перенаправляет вывод; для этой задачи ответ — **только файл** `solution.json`.

Образцы: каталог **`examples/`** (те же алгоритмы, что в docker-zip, но без `Makefile`).

## Docker-решения (zip + образ `nsuts-docker-base`)

Посылка — **zip-архив** с проектом в **корне** (без вложенной лишней папки «обёртки»).

### Makefile

Тестер по умолчанию выполняет:

1. **`make build`** — один раз после отправки (сборка в отдельном контейнере).
2. **`make --silent run`** — на **каждый** тест (новый контейнер).

Минимальный шаблон:

```makefile
build:
	# компиляция / pip install / Pkg.instantiate() и т.д.

run:
	# запуск; результат в solution.json
```

- Рецепты с **табами**, не пробелами (Unix-формат строк LF — как в примерах zip).
- Цель **`run`** должна быть **тихой**: `make --silent run` не должен засорять stdout (иначе возможны проблемы с перехватом вывода). Диагностику — в **stderr** или в файлы в `/solution`.
- Сборка и запуск идут в **`/solution`** (распакованный zip на хосте тестера).

### Вход/выход

Тот же контракт, что выше: в **`/solution`** лежат **`instance.json`** и нужно создать/перезаписать **`solution.json`**. Файлы текущего теста также монтируются в `/solution` под теми же именами.

### Тонкости sandbox

- **Read-only root**, запись — в **`/solution`**, **`/work`** и **`/tmp`** (в т.ч. `HOME=/tmp`).
- **Build и run — разные контейнеры.** Всё, что нужно на run (бинарник, `.venv`, `Manifest.toml`, кэш пакетов), должно лежать **под `/solution`** на диске тестера, а не только в `/tmp` внутри build-контейнера.
- **Julia:** в `Makefile` задайте  
  `export JULIA_DEPOT_PATH := /solution/.julia`  
  чтобы после `Pkg.instantiate()` на build пакеты были видны на run. Иначе на run будет "package not installed". Также не увлекайтесь с количеством используемых пакетов: время на компиляцию ограничено и включает прекомпиляцию пакетов.
- **Python:** типичный паттерн — venv **`.venv` в корне zip** (см. `docker_standard_python.zip`).
- **Сеть** в контейнере доступна на этапе скачивание зависимостей при build; на run доступа в сеть нет.
- Не используйте **`rename`** поверх смонтированного `solution.json` — запись должна идти **напрямую** в файл.

### Образ

Базовый образ **`nsuts-docker-base`** содержит, среди прочего: g++, Python, OpenJDK, Go, Rust, Julia и часто используемые библиотеки. Язык и зависимости, которых нет в образе, нужно собирать в **`make build`** (как в вашем `requirements.txt` / `Project.toml`).

### Примеры zip

| Архив | Содержимое |
|-------|------------|
| `docker_standard_cpp.zip` | `main.cpp`, `Makefile` → `g++`, `./solution` |
| `docker_standard_python.zip` | `solve.py`, `requirements.txt`, venv |
| `docker_standard_java.zip` | `Main.java`, `classes/` после build |
| `docker_standard_julia.zip` | `solve.jl`, `Project.toml`, `JULIA_DEPOT_PATH` |

Распакуйте zip локально, соберите в том же образе (`docker run ... make build && make run`), проверьте на тестовом `instance.json` из open-пакета задачи.
